## RAF Georgia rename-duplicate cleanup (prod data fix, later session)

Mike noticed the hype ratings on Tsarukyan vs Khamitov (RAF Georgia, July 11) had vanished.

**Root cause:** the 2026-07-10 17:45 UTC daily scrape saw Tapology rename fighters (e.g. "Khamitov" → "Kuat Khamitov"). The scraper matches fighters by name, so a rename creates a **new Fighter row → new Fight row** (Fight identity is `(eventId, fighter1Id, fighter2Id)`). The old fight then goes missing from the scrape and gets CANCELLED — stranding user data on a cancelled duplicate. Same failure class as `docs/HANDOFF-bkfc-duplicate-fight-root-cause-2026-05-30.md` and the Tapology bleed residual cleanup.

Three rename-dups from that one scrape:
1. **Tsarukyan vs Khamitov → Kuat Khamitov** — 4 hype predictions stranded (10, 7, 8, 8)
2. Retherford vs **Elnazar Akhmataliev → Ernazar Akmataliev** (also side-swapped) — no user data
3. Jacques vs **Razambek Jamalov → Zhamalov** — no user data

Two other CANCELLED rows on the card are **genuine opponent changes**, left alone: Vinesh → Sangeeta Phogat (vs Nichita), Real Woods → Brock Hardy (vs Alibegov).

**Confirmed double-fire:** creating the dup fight made the BOOKED lane instantly re-push to a user who'd already gotten booked (Jun 3) + 3-day (Jul 8) notifications for the original fight — fresh matches have null sent-stamps, so every rename-dup re-notifies followers. Concrete evidence for the notif double-fire-suppression follow-up.

**Fix applied (prod DB, one-off tsx scripts, since deleted):**
- Moved the 4 `FightPrediction` rows to the live fight `3aea951f` (guarded against user overlap).
- Merged notification matches: for the double-fired user, kept the fresh match, backfilled `threeDaySentAt` (prevents 3-day re-fire), re-pointed the 2 `FollowNotificationEvent` engagement rows to the surviving match + live fight, deleted the old match; moved the other 3 matches wholesale.
- Deleted the 3 dup fights and 2 orphaned fighters (empty-first-name "Khamitov", "Razambek Jamalov"); Elnazar Akhmataliev kept — referenced by another fight.

**Verified:** live fight `arman-tsarukyan-vs-kuat-khamitov` has all 4 hype predictions + 4 matches with correct sent-stamps; card shows only the two legitimate opponent-change CANCELLED rows.

**Not fixed (scraper-side root cause):** any Tapology rename still forks fighter+fight. Fix ideas (ties into the BKFC `upsertFightSwapAware` plan): match fighters by Tapology URL/ID before name; on insert, detect an existing same-event fight sharing one fighter ID + similar opponent name → rename in place; suppress BOOKED dispatch when the same user+fighter+event was already booked-notified.
