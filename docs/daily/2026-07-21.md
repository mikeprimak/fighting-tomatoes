# 2026-07-21 — Journalist-pitch sending identity set up (Zoho alias)

## What happened

Cleared blocker #1 on the Round Numbers #1 journalist send: a personal-name sending

## The plan said "real user, not alias". Reality said alias.

`docs/daily/2026-07-20.md` and the CLAUDE.md Next Session block both instructed
creating `mikeprimak@goodfights.app` as a real Zoho user (Users → Add User), on the
assumption the org was on Zoho's Forever Free 5-user tier.

Two things were wrong with that:

1. **Users live in the Admin Console (`mailadmin.zoho.com`), not the mail client.**
   The mail client at mail.zoho.com has no user management at all. Cost a few minutes
   of hunting.
2. **Add User failed: "You do not have enough licenses."** The org has exactly 1 seat.
   Zoho's free plan does allow 5 users but is only offered in selected data centers,
   and newer signups land on a single-seat plan instead. Adding a second real user
   would have meant a paid plan.

**Call: use an alias instead.** Aliases don't consume a license, so this was free.
For 41 cold emails, inbox separation wasn't worth a plan migration.

### Zoho org structure (non-obvious, worth recording)

The Zoho user's **login is `avocadomike@hotmail.com`**. `contact@goodfights.app` is a
mailbox *on* that user, not a user in its own right. So the Users list shows
`avocadomike@hotmail.com` and nothing that looks like the domain — aliases get added
under that user, Mail tab → Email Aliases. This is confusing enough that it burned a
step and is why it's written down here.

### What got set up

- Alias `mikeprimak@goodfights.app` on the existing user
- Display name set to **Mike Primak**, so the From line reads
  `Mike Primak <mikeprimak@goodfights.app>` rather than the Good Fights support identity
- Reply-routing filter **skipped** — replies land in the main inbox. Fine at 41 emails;
  revisit only if it gets noisy

### Why a personal-name address at all

`contact@` reads as a support queue. Cold pitches to journalists get replies at a much
better rate from an identifiable person. Alias sends authenticate on the domain's own
DKIM/SPF (verified healthy 2026-07-20), so there is no deliverability penalty versus a
real mailbox.
