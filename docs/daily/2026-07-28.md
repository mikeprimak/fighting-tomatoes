# 2026-07-28 — WebP profileImage root cause + outreach strategy change + video visual upgrade

## 1. The WebP profileImages were RAF's, not the enrichment path (`44a5eb44`)

Yesterday's follow-up said "stop the enrichment path writing .webp to
profileImage." The enrichment path was innocent — it never writes
profileImage at all. The writer is the **RAF daily scraper**: its parser had a
comment saying "Upload athlete image to R2 if available" and then assigned the
raw Webflow URL (`cdn.prod.website-files.com/...webp`) without uploading.
Event banners went through R2; fighter headshots never did. 164 fighters in
prod carried WebP profileImages, refreshed daily (rows stamped `updatedAt` =
today), which is why the OG route kept finding new ones. Guida / Cejudo /
Tsarukyan pointed at Karate Combat yesterday, but they're RAF signees too —
the roster overlap hid the real writer.

Three layers shipped:

- **`imageStorage.ts`** — every upload now sniffs magic bytes
  (`sniffImageFormat`) and transcodes anything Satori can't decode
  (`ensureDecodableRaster`): WebP/AVIF/unknown → PNG when the image has alpha
  (headshot cutouts keep transparency), JPEG otherwise. Applies to URL uploads
  and the local-file path (Oktagon crops). The early R2 dedupe check only
  short-circuits for already-safe URL extensions, since a transcoded upload's
  final key isn't knowable until the bytes are sniffed.
- **`rafDataParser.ts`** — all three fighter-image write sites now route
  through `uploadFighterImage` instead of hotlinking Webflow.
- **`fixWebpProfileImages.ts`** — idempotent backfill; ran against prod:
  **164/164 re-hosted on R2, 0 failures**. Only writes when the upload
  produced a different, non-WebP URL, so a failed upload can never rewrite a
  row with its own bad value.

Verified: prod query shows 0 WebP/Webflow profileImages remaining, and
`goodfights.app/fights/brian-ortega-vs-clay-guida/opengraph-image` (a 500 in
yesterday's incident) returns 200 `image/png`. 14 assertions in
`imageStorage.formatSafety.test.ts` (tsx assert script) cover sniffing,
pass-through byte-identity, alpha preservation, and non-image bytes throwing.

Yesterday's `e6aa91ae` (OG route degrades to placeholder on undecodable
images) stays — it's the right belt to this suspenders.

## 3b. Video: action-photo backgrounds + motion pass (`02971ed6`)

Mike's concern: the renders look basic next to combat-sports shorts built on
fight footage. Decision made in-session: **no fight footage** — Good Fights is
a named business with an acquisition thesis, and Zuffa enforcement (strikes,
not just claims) plus buyer-diligence optics make clip content the wrong
trade. Stills at low opacity are the accepted middle: much lower exposure, and
the plan is press-kit / licensed / CC photos first (small orgs will say yes if
asked — fits the new relationship-first outreach).

Shipped in `packages/video`:

- **Per-fight background slot.** `public/backgrounds/<fightId>.<ext>`
  (gitignored — public repo, rights are per-file decisions) baked into
  `src/data/backgrounds.json` by `scripts/syncBackgrounds.mjs`, chained into
  render/studio/still and the panel. Photo renders desaturated at ~25%
  opacity with a slow push-in, vignette + safe-zone scrim. The panel gained a
  **Backgrounds card** with per-fight upload/replace/remove (server names the
  UUID file itself) — hand-naming was the error path.
- **Spoiler guard:** the hook's backdrop comes from the lowest-ranked fight
  with a photo, heavily blurred — never #1's, the payoff must not leak.
- **No-photo fallback:** drifting ambient arena glow, so photo-less cards
  don't read flatter than photo cards.
- **Motion pass:** film grain over every scene (animated SVG turbulence tile),
  Ken Burns push-in on all headshots, impact settle on the whoosh landing,
  number-pop halo flares on the beat and rests.
- **Panel bug found while wiring the UI:** the 1.2s state tick re-rendered the
  captions card's innerHTML every tick, rebuilding the textareas mid-edit.
  Pull/captions cards now redraw only when `generatedAt` changes.

Verified by stills at hook / card-with-photo / payoff / card-without-photo
frames and an end-to-end panel upload → manifest → delete round-trip. The
wrong-fight rule extends to photos: a backdrop must be from the fight on the
card (README + memory updated). ElevenLabs VO remains the publish blocker.
