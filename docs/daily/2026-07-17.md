# 2026-07-17 — GA4 conversion events: why zero arrived, sendBeacon relay fix

## What happened

Session goal was walking Mike through the GA4 key-events manual step
(`docs/HANDOFF-ga4-key-events-2026-07-14.md`). Pre-checked with
`ga.js --report events` first: **zero** `rating_submitted` /
`hype_submitted` / `app_download_click` in the 3 days since the code
shipped, despite ~7.5k active users and at least one real desktop
banner-click-through to `/download` (sessionMedium=banner pageview existed
with no matching event).

## Root cause (proven empirically with headless Chrome against prod)

1. The click listener works — `app_download_click` IS pushed to `dataLayer`
   on click (verified by preventing navigation and inspecting).
2. gtag.js batches events for **~5 seconds** before sending
   (`/g/collect`). Measured: event request leaves at +5016ms.
3. `transport_type: 'beacon'` does NOT bypass the batch (still 5s).
   `event_callback` fires at +4ms while the hit leaves at +5s — it lies.
4. **gtag drops the queued events silently when the page navigates away.**
   Pushed an event, navigated 400ms later, watched all requests for 9s:
   the event never left, before or after unload. No pagehide flush.

Every `app_download_click` is a click that immediately navigates (banner,
navbar, blog links are plain `<a>`; store buttons leave the site), so 100%
of them died in the queue. `rating_submitted`/`hype_submitted` don't
navigate, so their zeros are plausibly genuine (web ratings need login).

## Fix shipped

- **Backend:** new `POST /api/track/ga`
  (`packages/backend/src/routes/track.ts`, registered under `/api/track`) —
  relays whitelisted events to the **GA4 Measurement Protocol** with the
  server-held API secret. Accepts `text/plain` JSON (sendBeacon can only
  carry CORS-safelisted content types; a preflight can't complete during
  unload). Always 204. No-ops without `GA4_MP_API_SECRET`. Payload shape
  validated against Google's `/debug/mp/collect` (zero validation messages);
  route behavior covered by fastify `inject` tests (all paths 204, garbage
  bodies safe).
- **Web:** `trackEventBeacon` in `packages/web/src/lib/analytics.ts` —
  PostHog via `posthog.capture(..., { transport: 'sendBeacon' })`, GA via
  `navigator.sendBeacon` to the relay with `client_id` from the `_ga`
  cookie and `session_id` from `_ga_WV5RKCMJSB`. Falls back to plain gtag
  when cookies/beacon are unavailable. `DownloadClickTracker` and
  `/download` `StoreButtons` switched to it.
- `.env.example` documents `GA4_MEASUREMENT_ID` / `GA4_MP_API_SECRET`.
