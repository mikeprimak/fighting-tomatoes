## UFC daily scraper: 4 days of failures, fixed

Mike got failure emails Jul 17+18; runs were actually red Jul 15–18 (last
green Jul 14). NOT related to the repo going private — the runs executed
fully and died inside the scrape step. Root cause: a fighter scraped from
ufc.com has a null `record`, and `parseRecord` in
`packages/backend/src/services/ufcDataParser.ts` called `.split()` on it
unconditionally, crashing the whole import ~130 fighters in. The Karate
Combat and BKFC parsers already null-guard; UFC's never did. Fix: same
guard (null → 0-0-0). Verified with a manual `workflow_dispatch` run:
**success**. Commit `794578c8` (post-rewrite hash).
