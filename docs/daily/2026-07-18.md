## Shipped: fighter next-fight / last-fight SSR answer blocks (`a6fd9113`)

Own The SERPs front-load #5 — the "who is X fighting next" / "when did X
last fight" query family.

- New server component `packages/web/src/app/fighters/[id]/FighterFightStatus.tsx`,
  rendered between the physical-facts strip and About (passed into
  `FighterDetailClient` as a `fightStatusBlock` ReactNode slot so it sits
  inside the page column).
- Two answer cards in SSR HTML: "Next fight" ("Islam Makhachev's next fight
  is against Ian Machado Garry at UFC 330: Makhachev vs. Garry on Saturday,
  August 15, 2026." + fight-preview and full-card links) and "Last fight"
  ("… last fought Jack Della Maddalena at UFC 322 on …" + See fan ratings
  link).
- **Spoiler-safe by construction**: opponent + event + date only, never the
  result. Spoiler-free mode defaults ON for logged-out visitors and this
  block is static HTML for everyone, so results stay on the fight page
  behind the client gate.
- States: LIVE ("is fighting right now"), TBA opponent ("opponent has not
  been announced yet"), no booked fight ("does not have a fight booked
  right now" — only shown when the fighter has history), zero fights →
  renders nothing.
- Meta description now **leads** with the next-fight sentence when one is
  booked (fights fetch in `generateMetadata` deduped with the page body's
  identical fetch). SERP snippet answers the query directly.
- Derivation: `/api/fights?fighterId=` default sort is `event.date desc`,
  so upcoming fights are always inside the 50-row window; next = soonest
  UPCOMING/LIVE, last = most recent COMPLETED, CANCELLED ignored.

Verified SSR locally (Makhachev booked-case, Topuria no-fight-booked case)
and live in prod post-deploy (HTML sentence + meta description). Web tsc 0.
