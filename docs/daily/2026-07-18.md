## Three real bugs the dry run caught (none were visible from types)

- **Brave 422 — query over 400 chars.** The 14-domain OR clause plus the longer
  reaction intent hit 414 chars and Brave rejected the entire call. This was
  latent for the existing modes too, one intent-string edit away from killing a
  live pass silently. Fixed generically: `buildQuery()` drops lowest-preference
  domains until the query fits.
- **Quote scoping silently slid down the card.** `loadCompletedCard` filters to
  `aiPostFightEnrichedAt: null`, so "top 2 by orderOnCard" meant *top 2 of what
  is left* — on any already-recapped event that is two prelims, not the main
  event. On UFC 329 it picked Riley vs Kamaka and Wang vs Cortez instead of
  McGregor vs Holloway. Fixed with a separate `loadQuoteTargets` over the FULL
  card; quote-only fights ride in the card so they are quotable and are held out
  of recap persistence via `recapEligibleFightIds` so their existing recaps are
  not overwritten.
- **Prompt returned `[]` every time.** The reaction sources are "pros react"
  roundups that reproduce X posts and podcast lines; the prompt never blessed
  that, so Haiku treated all of it as ineligible. Added an explicit
  what-counts-as-a-quote section with worked examples.

## The verifier is the point of this feature

The substring gate is stricter than any other enrichment gate on purpose:
misquoting a named journalist is a different failure class from a soft narrative
line being a bit off. It demonstrably works — on the first passing run it
rejected a Kenny Florian quote.

That rejection turned out to be a **false positive worth fixing**: cheerio's
`.text()` concatenates block elements with no separator ("…flying kick.His
planting leg…"), so a correctly-copied quote fails a raw substring test once the
model re-inserts the space a human reader infers. The comparison now ignores
whitespace entirely. This costs the guard nothing — word choice, order and
spelling still must match character for character. `verifyPunditQuotes.test.ts`
pins both halves: paraphrase, reordered clauses, stitched-across-a-gap, a single
swapped word, and a real quote cited to the wrong URL all still reject.

Note the repo's "test" convention is `tsx`-runnable assert scripts, not jest
(`jest.config.js` is a 3-byte stub) — the test follows `fighterRename.test.ts`.
