# 2026-07-06 — Vercel free-tier overage: bulk crawlers blocked

## Problem

Vercel emailed: team `michael-primaks-projects` used **100% of the free tier's 1M edge requests** — projects get paused if usage exceeds the cap. All usage graphs show a ~5x jump on **July 2** that never came back down.

## Diagnosis

- GA4 shows only ~1,300 human pageviews in the last 7 days — this is not people.
- Vercel runtime logs (web project, 24h) show **1,216 distinct paths** hit, multiple requests/second, walking the deep fight catalog (`/fights/kazushi-sakuraba-vs-royce-gracie` etc.) with `cache=MISS` on every SSR page, plus the same static pages (`/login`, `/privacy`, `/blog`) hit several times per second.
- Timing is conclusive: the **programmatic SEO corpus (~5.5k pages) + sitemaps went live July 1–3**. Bulk crawlers (AI-training scrapers, SEO-tool bots) found the sitemaps and have been hammering the long tail ever since. Googlebot paces itself on small sites; this swarm pattern is the junk tier.

## Fix (shipped)

1. **Vercel firewall rule "Block bulk crawlers"** (live, published via `vercel firewall` CLI from `packages/web`): denies user agents containing Bytespider, Amazonbot, PetalBot, GPTBot, ClaudeBot, CCBot, meta-externalagent, SemrushBot, AhrefsBot, MJ12bot, DotBot, BLEXBot, DataForSeoBot, ZoominfoBot, ImagesiftBot, Diffbot, Timpibot, serpstatbot. **This rule lives in Vercel, not git.**
2. **robots.txt ban** (`packages/web/src/app/robots.ts`, commit `e0ae8c09`): same list plus robots-only tokens (Google-Extended, Applebot-Extended, FacebookBot). Compliant bots stop *requesting* entirely — that's what actually reduces edge-request count, since firewall-denied requests still count toward the quota.

**Deliberately still allowed:** Googlebot, Bingbot (the whole point of the SEO workstream) and user-triggered AI retrieval agents (OAI-SearchBot, Perplexity-User/PerplexityBot, ChatGPT-User, Claude-User) — low volume, and citations in AI answers are distribution.

Mike's call.
