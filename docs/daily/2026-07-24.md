# 2026-07-24 — RIZIN Landmark 15 corruption (user feedback d708305f)

## Report

Kevin Sartori (Android 2.1.3, feedback `d708305f-2b49-40bd-b6d7-bf22b55f5137`):
Landmark 15 was missing Kojiro Shiba vs. Haruto, then started "showing a bunch
of fights from a different event."

## Root cause

`discoverTapologyUrl`'s keyword fallback (copy-pasted in `scraperService.ts`,
`runTapologyLiveTracker.ts`, `backfillTapologyResults.ts`) matched event-name
words of length > 2 against hub-page URLs and accepted any link with ≥ 2 hits.
For numbered series this is fatal: "Rizin FF - Landmark Vol. 15" reduces to
`rizin/landmark/vol` (the "15" is dropped by the length filter), so the FIRST
Landmark link on the Tapology RIZIN hub page wins, whatever its number. The
mismatched URL is then **persisted to `event.ufcUrl`**, and the nightly
`backfillTapologyResults` VPS cron scrapes that page — `tapologyLiveParser`
creates every fight it doesn't recognize, importing a foreign card wholesale.

Chain found in prod:

- Landmark 15 → pointed at Tapology **Landmark 13** page (137827); L13's whole
  card (16 fights) imported into L15 on 2026-07-23, forking 3 dup fighters
  (Ryusei Imamura, "Yu-ki", S. Payaklamphong).
- Landmark 13 → pointed at Tapology **Landmark 14** page (140753); 12 of L14's
  fights imported into L13 on 2026-05-29 (stuck UPCOMING on a COMPLETED event).
- Shiba vs. Haruto was missing because the RIZIN daily scraper is
  Sherdog-based and Sherdog's card lacked it (kickboxing bout); the Tapology
  backfill would have added it — but it scraped the wrong page.

## Fixes

**Data (prod, via script):**
- Deleted the 16 foreign fights on L15 and 12 on L13 (all zero engagement,
  verified counts before delete) + the 3 orphaned dup fighters.
- Corrected `ufcUrl` on L13 (137827-…landmark-13), L14 (140753-…landmark-14),
  L15 (140754-…landmark-15).
- Re-ran `runTapologyLiveTracker.ts <eventId>` **on the VPS** (local runs fail
  Cloudflare — no `TAPOLOGY_PROXY` in the local .env; the DataImpulse+CapSolver
  stack lives on the VPS). L15: all 16 fights got winners/methods, and the
  missing **Kojiro Shiba vs. Haruto was created (Shiba by UD)**.
- Post-run cleanup: Tapology spells "Jae **Hoon** Lee" vs our "Jae **Hun** Lee",
  so the parser created a dup Takagi fight + fighter — merged the result onto
  the existing rated fight, deleted the dup pair, and slotted Shiba vs. Haruto
  at its real card position (order 12, Main Card).

**Code (root cause):**
- New `src/utils/tapologyEventMatcher.ts` — shared `matchTapologyEventLink()`
  replacing all three copy-pasted discovery matchers. Rules (tuned against
  real prod URLs, see the unit test): CONFLICT-only numeric guard (a link is
  rejected only when it carries numbers that don't cover the event name's —
  number-less slugs like `144122-zuffa-boxing` stay eligible); roman numerals
  ii–xix in slugs count as numbers (`mvp-showcase-ii`); keyword scoring counts
  event words in slug + link display name and requires a UNIQUE best candidate
  (generic Zuffa slugs disambiguate via fighter names; ties refuse to guess).
- Unit test: `src/utils/tapologyEventMatcher.test.ts` (tsx assert script,
  11 cases incl. the incident and every prod shape the guard must not break).
- `backfillTapologyResults.ts` switched off its private `new PrismaClient()`
  to the `lib/prisma` singleton (per the 2026-06-06 connection-pool rule).

## Verification

- Matcher unit-tested against the real hub-link set: Vol. 13/14/15 each map to
  their own page; "Landmark Vol. 16" (absent) returns null; no-number names
  still match.
- Backend `tsc --noEmit` clean.
