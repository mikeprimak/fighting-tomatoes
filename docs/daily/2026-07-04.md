# Session (parallel window) — intent-aware search overhaul (backend + mobile + web)

Goal: "Conor" → McGregor on top with his next fight (Holloway, UFC 329) first; exact fighter queries ("rose namajunas") get a featured, more detailed fighter block; predictive search box on both clients; promotions/events surfaced everywhere.

## Backend (`src/routes/search.ts` — rewritten)

1. **Fights are now relevance-ranked in JS** (was: raw event-date-desc, take 10). Over-fetches 3× candidates, scores each fight by `max(best participating fighter's name-match score, 0.4 × event name/promotion score)`, tie-breaks by **fighter prominence** (career bouts), then upcoming-before-completed-before-cancelled, then date (upcoming soonest first). "conor" now returns McGregor vs Holloway first, then his completed fights by recency.
2. **Exact single-name matches are one tier** (750) — was first=700 < last=800, which put an obscure "John Conor" (0 fights) above Conor McGregor. Prominence tie-break (champion > career bouts, with wins+losses+draws fallback since `totalFights` drifts for non-UFC) now decides.
3. **Full-name-prefix tier (920)** — mid-typing "rose nam" used to rank Tyson Nam (exact last "nam") over Rose Namajunas (substring, 250). A query that's a prefix of `first last` now outranks bare last-word matches.
4. **`data.featured`** — when the top fighter scores ≥700 (exact first/last/full/nickname), response includes `{ type: 'fighter', fighter, nextFight, lastFight }`. The fighter's upcoming (take 2) + last completed fights are force-fetched into the candidate pool so the date-ordered take can't miss them; `nextFight`/`lastFight` are the fully-enriched fight objects (hype, user data).
5. **New `GET /api/search/suggest`** — lightweight typeahead (no auth, 3 parallel queries, no per-fight enrichment): top 5 fighters (avatar/record/champion), 3 events, 3 promotions. Event candidate pool is `orderBy date desc, take 50` so "ufc 329" actually finds UFC 329 (unordered take-20 returned arbitrary Fight Nights). ~0.5–0.8s from local against Render; will be much faster on-network.
6. Fight fighter1/fighter2 selects now include `wins/losses/draws` (cards' `Fighter` type wanted them).

Verified live against prod DB (local server, port 3010): "conor" (featured McGregor + Holloway fight first), "rose namajunas" (featured, no next fight → lastFight UFC 324), "jon jones", "ufc" (upcoming events + UFC promotion), "ufc 329", "rose nam", "conor mc", "mcgre".
