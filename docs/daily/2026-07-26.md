actually exists, then rebuilt the weakest one.

### Two things caught during review

1. **Data drift, exactly as the doc warned.** The June top-5 no longer holds: 9.76 → 9.75,
   and Henderson vs Rua dropped out entirely, replaced by Topuria vs Gaethje at #5. Always
   re-run the data script before a render.
2. **A false claim in the hook copy.** The draft read "FANS RATED EVERY UFC FIGHT EVER."
   Only **7,054 of 8,945** UFC fights carry a rating. Fixed, and the number is now queried
   into the payload as `corpus.ratedFights` so the copy cannot drift ahead of the data.
   The "no superlative outruns the table" rule from Round Numbers applies to video too.

## Shipped: local control panel (`c0e01187`)

`cd packages/video && pnpm panel` → http://localhost:3009. Format picker, pull from prod,
caption editor, render, in-page preview. Plain Node http server, zero new deps.

**Why not the Render admin panel:** rendering needs headless Chrome and ~3 min CPU; the
Render instance is 256 MB and `packages/video` is excluded from the deploy image on
purpose. Putting it back would undo the isolation. The panel drives the same commands
locally.

Also fixed in the same pass (`9b975510`): pulling a new format wrote `<format>.json` while
the Remotion root statically imported `top-fights.json`, so `pnpm render` silently
re-rendered the old top-5. Every pull now also writes `current.json`, which is what the
root reads. Hook headline became per-format (`corpus.scopeRatedFights`) and auto-fits.

**Data-quality trap the panel now surfaces:** the 2023 pull ranked a 13-vote 9.31 above a
44-vote 9.20. Narrow scopes (one year, one division) hit this constantly at the default
vote floor of 10. The panel flags any fight under 20 votes; raise "Min votes" before
publishing anything scoped narrower than all-time.

## Panel UX fix (`9850230d`)

Two failure modes hit during a live walkthrough with Mike, both fixed:

1. **`pnpm panel` from the repo root fails** (`ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL`). It
   must run from inside `packages/video` — the package is outside the workspace, so root
   pnpm cannot see the script. This is a permanent consequence of the deploy isolation,
   not a bug; documented in the README.
2. **Starting it twice crashed with a raw `EADDRINUSE` stack trace**, which reads as a
   breakage when the panel is actually up and serving. Now prints "The panel is ALREADY
   RUNNING" + the URL and exits 0. Added `pnpm panel:stop` for panels orphaned by a
   closed terminal (Ctrl+C is unavailable once the window is gone).

## Operator runbook (the whole loop)

```
cd C:\Users\avoca\fight-mobile-app\packages\video
pnpm panel            # -> http://localhost:3009   (pnpm panel:stop to kill an orphan)
```

1. Pick format · 2. **Min votes: 10 all-time, 25+ for year/weight-class** · 3. Pull from
production (~20s) · 4. Write one caption line per fight, Save · 5. Render (~3 min) ·
6. Plays in-page, file in `out/`.

Whatever was pulled last is what renders. Renders are silent.
